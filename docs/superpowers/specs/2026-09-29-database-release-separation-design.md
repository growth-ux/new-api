# 达梦数据库初始化 SQL 与程序启动分离

状态：已按方案实施。更新日期：2026-09-29。

## 目标

生产使用全新达梦空库。部署人员先执行 SQL，再启动程序。本次仅调整启动阶段：达梦不再自动建表、改表或修改索引、约束，并移除专门为这些操作准备的迁移检查。历史数据回填、旧配置转换和正常业务初始化保持原逻辑；运行过程中的业务操作不改。

仅调整达梦路径。MySQL、PostgreSQL、SQLite、ClickHouse 等其他数据库保持现有初始化、自动迁移及相关行为，不为它们新增 SQL 部署方式。

不增加版本表、启动版本校验、迁移执行器、发布状态管理或自动结构检查。

## 1. 提供独立 SQL

只生成一个 `database/dm8/init.sql`，包含当前程序需要的表、字段、索引、约束和必要初始数据，不再拆分其他 SQL 或新增 README。

唯一新增的部署脚本：

```text
database/dm8/init.sql
```

- `init.sql` 用于全新达梦库，包含业务表、日志表和审计表；主库兼作日志库时，完整执行一次即可。
- 如配置独立达梦日志库，在该库执行同一个文件中用注释标明的日志及审计部分，不额外生成日志库脚本。该部分包含所需全部表和索引，不依赖业务表。
- 达梦脚本包含正确的字段类型、软删除唯一索引，以及业务锁表所需的固定记录。
- SQL 与现有模型的表名、字段名及大小写引用方式保持一致；覆盖全部启动迁移对象，包括单独迁移的 `subscription_plans`、审计表和达梦辅助锁表。
- 锁表和索引只是改由 SQL 提前创建；邮箱操作的业务加锁、软删除后的名称复用规则保持原样。现有程序负责的数据初始化不因本次调整全部搬入 SQL。
- 不在 SQL 中设置固定管理员密码或登录私钥，管理员创建等继续走现有业务流程。
- 必要的执行说明、目标 schema 要求和分段说明直接写在 `init.sql` 注释中。

本次只处理空库初始化，不提前新增升级脚本、校验脚本或其他部署文件。`init.sql` 放在 Git 中管理，不要求人工维护数据库版本号。

## 2. 达梦启动不再自动迁移表结构

集中处理现有启动路径，不顺带重构业务：

| 位置 | 要做的调整 |
| --- | --- |
| `model/main.go` 的 `InitDB`、`InitLogDB` | 根据实际连接方言跳过达梦结构迁移，保留连接、连接池设置及原有数据初始化，其他数据库继续原流程 |
| `migrateDB`、`migrateLOGDB` 及其辅助函数 | 拆开结构迁移和数据处理，仅跳过达梦建改表及索引、约束变更；不能跳过整个 `migrateDB()` 后遗漏其中的数据处理，其他数据库保持原流程 |
| `model/audit_log.go` | 日志实际存储为达梦时，不在启动时创建审计表；覆盖主库兼作日志库的分支 |
| `model/dm8.go` | 移除为迁移准备的系统字典权限预检，保留正常连接处理 |
| `ensureUserQuotaColumns` | 达梦跳过启动字段类型探测，初始化 SQL 使用正确类型；此检查在主从判断之前，达梦主从节点均需跳过，其他数据库检查保持原样 |
| 达梦锁表和软删除索引初始化 | 将建表、插入固定锁记录、建索引的动作移到 SQL；保留邮箱业务行锁、软删除唯一性规则和 CRUD 适配 |

历史数据回填和旧配置转换不属于本次改动范围。`InitializeUserAuthVersions`、`InitializeExternalIdentityClaims`、`MigrateRetiredFrontendOptions` 保留原有执行条件和逻辑。拆分 `migrateDB()` 时，确保其中的数据处理仍在对应表已由 SQL 建好后按原顺序执行，不能随结构迁移一并跳过。

结构迁移也包含 `migrateOptionPrimaryKey` 等自动修表步骤，以及末尾单独执行的 `AutoMigrate(&SubscriptionPlan{})`。达梦启动时应一起跳过，不能只处理主 `AutoMigrate` 列表。正常数据回填仍仅在原有主节点条件下执行，不扩大到从节点。

主库与日志库分别判断实际方言，不能只用主库类型控制所有结构迁移。例如达梦主库配 ClickHouse 日志库时，只跳过达梦结构迁移，ClickHouse 原有建表和 TTL 行为保留；其他主库配达梦日志库时，仅达梦日志库提前执行 SQL。

保留 GORM 用于正常增删改查，不因为删除迁移而删除业务需要的方言适配。

角色权限加载、会话、任务、密钥生成及其他正常业务初始化和数据写入保持现有行为，不扩展为“启动完全只读”。不在这次改动中顺带重写权限系统、渠道修复或任务调度。若某处混合了结构升级与业务逻辑，先拆开；无法确定行为边界时向用户确认。

达梦运行账号不再为了自动迁移而要求 `SELECT ANY DICTIONARY` 或建改表权限。其他业务功能需要的权限按实际使用保留，并通过测试验证。

## 3. 验证改动

在隔离测试库执行，不能使用业务库清表测试：

1. 达梦空库仅执行交付的 `init.sql`，然后启动应用，验证登录、渠道、额度及日志等主要功能。
2. 覆盖达梦主节点、从节点、重复启动和多个实例启动，确认启动阶段不执行结构变更或迁移元数据查询；历史数据回填和旧配置转换仍按原有条件执行。
3. 用未授予字典查询和建改表权限的达梦测试账号验证；业务账号是否具有其他继承权限一并核对。
4. 验证达梦主库兼作日志库、独立达梦日志库，以及主库/日志库混用不同方言的配置，避免遗漏审计表或误停其他数据库迁移。
5. 达梦不执行初始化 SQL 时，程序不能自行创建或修复结构；实际数据库操作错误按正常错误路径处理，不新增专门检测功能。
6. 回归非达梦启动路径，确认原有自动迁移和字段检查等行为不变。
7. 验证 SQL 初始化后的邮箱并发写入保护，以及预填分组删除后可重用名称、未删除的同名分组仍被拒绝；这是现有业务回归验证，不改动相关运行期逻辑。

达梦初始化集成测试使用交付的 SQL 建库。其他数据库测试和普通单元测试中的 `AutoMigrate` 保持现有方式。

## 部署方式

```text
准备达梦数据库和账号 → 执行 init.sql → 配置连接信息 → 启动程序
```

初始化只面向空库，不在脚本中自动清空已有业务数据，不将重复执行初始化脚本当作升级方式。

本次实施仍包含前述启动代码调整和测试；SQL 部署文件只新增一个 `database/dm8/init.sql`，说明写在文件注释中，测试结果在交付时汇报。没有其他新增管理功能，其他数据库部署方式及现有数据处理逻辑不变。
